# Audio: soundtrack, sound effects, character voices

Everything you hear is generated by scripts in `Tools/audio/` and committed as ordinary audio files under `Assets/Resources/Audio/`. Nothing is recorded, licensed stock, or downloaded at runtime. To change a sound, edit its script and re-bake. Don't hand-edit the clips.

| Layer | Script | Output | Runtime |
|---|---|---|---|
| Soundtrack | `render_music.py` | `Resources/Audio/Music/` | `Runtime/Audio/AdaptiveMusic.cs` |
| Sound effects | `render_sfx.py` | `Resources/Audio/Sfx/`, `Resources/Audio/sfx_*` | `Runtime/DemoAudio.cs` |
| Character voices | `render_voices.py` | `Resources/Audio/Voices/` | `Runtime/Audio/CharacterVoice.cs`, `OverseerVoice.cs` |
| Live voice lines (optional) | `voice_server.py` | nothing, speaks on demand | `Runtime/Audio/VoiceServerLink.cs` |

All volumes go through `SoundBus` (channels Ui / Sfx / Ambient / Music / Voice, with ducking). The Settings sliders are Master, SFX, Ambient, Music and Voice. Settings → **CHARACTER VOICES** turns spoken barks and the Overseer on and off.

## Setup (only to re-bake or run live voices)

```bash
Tools/audio/setup.sh   # Python 3.12 env + Kokoro-82M weights (~120 MB, Apache-2.0, checksum-verified)
```

Windows: create `Tools\audio\.venv` with Python 3.12, `pip install -r Tools\audio\requirements.txt`, and download the two files listed in `setup.sh` into `Tools\audio\models\`.

The game does not need any of this. The baked files ship in `Resources`.

## Soundtrack

`Tools/audio/render_music.py` (with `music_dsp.py` for oscillators, filters, reverb and dynamics) composes and renders the score deterministically. One leitmotif runs through every world: a rising 1–5–8 call, then an answer that climbs past the octave and lands open on the fifth. Each world restates it with its own key, tempo and instruments:

| World | Key | Tempo · loop | Colour |
|---|---|---|---|
| Earth | F major | 96 bpm · 80.0 s | Warm pad and strings, electric-piano arpeggio, soft kit, horn-synth motif, glockenspiel |
| Luna | E dorian | 72 bpm · 80.0 s | Glass pad over sub drone, sonar pings, sparse arpeggio, flute-like motif, FM bells, 6 s reverb |
| Mars | A dorian | 100 bpm · 76.8 s | Dusty saturated pad, wind, plucked ostinato, gritty syncopated bass, frame drums, war toms |
| Belt | G minor | 120 bpm · 80.0 s | Metallic pad, acid 16th bass, hammer kick, girder clangs, sidechain pump, bright saw motif |
| Europa | B minor | 64 bpm · 75.0 s | Ice choir, deep drones, heartbeat pulse, ice cracks, gliding sine motif at half speed, 8 s reverb |

Every world has four sample-locked stems that loop seamlessly: `bed`, `rhythm`, `harmony` and `threat`. The reverb and delay tails are rendered circularly, so they wrap into the start instead of fading. Every note comes from the world's scale, so any combination of stems stays in key. There is also `title_theme.ogg` (D major, 87 s loop) and `sting_victory` / `sting_defeat` (5.6 s each).

`AdaptiveMusic` loads the active world's stems, starts all four on the same DSP time with `PlayScheduled`, and crossfades their levels by colony mood (with hysteresis). Mood levels for bed / rhythm / harmony / threat:

| Mood | When | Levels |
|---|---|---|
| Calm | empty drop | 1 / 0 / .7 / 0 |
| Work | more than 2 modules | .9 / .9 / .75 / 0 |
| Tension | fauna threat > 0.22 or payroll thin | .85 / .6 / .45 / .65 |
| Crisis | threat > 0.55 or a critical alert | .75 / 1 / .25 / 1 |

World changes crossfade over 3 s. The title theme fades in whenever the solar-system title view is up. On victory and on a lost colony, the stinger ducks the score and Grok speaks after it. The SFX fanfare only plays if a stinger is missing. If any of a world's stems is missing, the original procedural synth takes over.

```bash
Tools/audio/.venv/bin/python Tools/audio/render_music.py              # all worlds + title + stings (~100 s)
Tools/audio/.venv/bin/python Tools/audio/render_music.py --world mars
Tools/audio/.venv/bin/python Tools/audio/render_music.py --check      # lengths, seams, headroom, loudness, key
```

Measured: the Work mix is about −17 LUFS (BS.1770), and every layer combination peaks at −1.5 dBFS or lower. Loop seams are clean before encoding. Vorbis adds a small −45 to −56 dBFS step at the file edge, so each world's files start at its quietest 16th-note boundary. Music size is 23 MB. If you ever hear stems flam, switch `Music/` from Streaming to Compressed In Memory in `AudioImportRules` (about 4.5 MB of RAM per world) for sample-accurate starts.

## Sound effects

`Tools/audio/render_sfx.py` (with `sfx_dsp.py`, `sfx_events.py`, `sfx_beds.py`) renders every event as layered, synthesised sound design with fixed seeds. There are 3 takes per event so repeats don't machine-gun. Output goes to `Assets/Resources/Audio/Sfx/`: short one-shots as mono WAV, long-tailed ones and stereo stingers as OGG, 11 MB in total. The old `Audio/sfx_*.wav` beeps remain as fallbacks, and so does procedural synthesis if a clip is missing.

```bash
Tools/audio/.venv/bin/python Tools/audio/render_sfx.py             # everything, ~10 s
Tools/audio/.venv/bin/python Tools/audio/render_sfx.py --only claim,bite
Tools/audio/.venv/bin/python Tools/audio/render_sfx.py --check     # peaks, DC, clicks, loop seams, loudness order
```

Loudness is set per tier (BS.1770 momentary max) so importance reads by ear:

| Tier | Events | Target |
|---|---|---|
| UI | ui_hover, ui_click, retry | −36 … −26 LUFS |
| Feedback | construction_tick, claim, credits, equip, heal, repair, extract, flag_post, build_place, robot_spawn, party_form, bite, robot_hit, stalker_growl, stalker_death | −25 … −20 |
| Milestone | robot_down, level_up, launch_ready, build_complete, research | −19.5 … −18 |
| Alert | alert_warning, fail, alert_critical | −17 … −15 |
| Fanfare | victory, launch | −13.5 … −13 |

Ambient beds: one per world, looping seamlessly, plus a "campus B" variation. Earth has wind and plant hum. Luna has a near-silent suit fan and hull ticks. Mars has thin wind and grit. Belt has far drills and creaks. Europa has ice groans and a deep drone.

`DemoAudio` picks takes without repeats (`Systems/SfxVariantPicker.cs`) and rate-limits each event (`Systems/SfxRateLimiter.cs`), so twenty robots claiming in one frame make one sound. World-positioned overloads (`PlayBite(at)`, `PlayBuildComplete(at)`, …) go through `SpatialAudio`. UI sounds and alerts stay 2D. Everything routes through `SoundBus`. The completion clunk now plays when construction actually finishes. Before, it played at placement, on top of the placement sound.

## Character voices

### The cast

Voices come from **Kokoro-82M** (Apache-2.0), rendered on your machine, plus a robot processing chain (`voice_fx.py`), because every speaker is a machine. The cast lives in `Tools/audio/cast.json`:

| Speaker | Callsign | Kokoro voice | Pitch | FX |
|---|---|---|---|---|
| Overseer (Grok) | — | `af_heart` | 0 | `overseer`: clean, slight digital doubling |
| Engineer Bot | Anvil | `am_onyx` | −1 | `servo` |
| Scout Drone | Horizon | `am_puck` | +3 | `drone`: small radio speaker |
| Defense Mech | Aegis | `am_michael` | −3 | `mech`: armoured resonance |
| Medic | Triage | `af_sarah` | 0 | `servo` |
| Harvester Bot | Strip | `am_echo` | −2 | `servo` |
| Surveyor Bot | Chart | `bf_alice` | +1 | `drone` |
| Terraformer Bot | Bloom | `af_aoede` | 0 | `servo` |
| Courier Bot | Haul | `am_liam` | +1 | `servo` |
| Geologist Bot | Core | `bm_lewis` | −1 | `servo` |
| Sentinel Mech | Rim | `bm_daniel` | −4 | `mech` |

Pitch changes keep the tempo: the line is synthesised at a compensating speed, then resampled. Formants move with the pitch, so drones sound small and sentinels big. At runtime each individual robot also gets a stable ±5 % pitch offset, so two Anvils don't sound identical.

### What gets said

- **Hero barks**: `Tools/audio/voice_lines.json`, 3 takes of 11 moments per class (`select`, `claim`, `refused`, `hunt`, `flee`, `repair`, `rest`, `wander`, `levelup`, `hurt`, `down`). Barks are short and name-free, because every robot of a class shares them. The hero's card line changes to match what was said (except for pain noises and hellos).
- **Overseer lines**: every scripted Grok line is taken from the C# sources at bake time: `GrokCatalog.Line`, `OverseerRules.Grok*`, fixed `CompactGrok` lines, and literal `RaiseAlert` messages. The game finds a clip by a hash of the line's normalised text (`VoiceBank.LineKey`, mirrored in `voice_common.py`). Anything passed to `GameLoop.LogOverseer` that has a baked clip is spoken. Status chatter stays text.
- **Overseer fallbacks**: warnings with no baked line get a generic alert (`alert_warning`, `alert_critical`, `module_lost`). With no bank at all, the original vocoder babble plays.

The bake is incremental and re-voices changed lines only. `VoiceTests.ShippedBank_*` fails if a Grok line or a hero moment has no clip. Run `render_voices.py` after editing copy.

```bash
Tools/audio/.venv/bin/python Tools/audio/render_voices.py             # bake what changed (~1 s per line on an M4)
Tools/audio/.venv/bin/python Tools/audio/render_voices.py --check     # CI-style check, no synthesis
Tools/audio/.venv/bin/python Tools/audio/render_voices.py --speaker hero.ScoutDrone --force
Tools/audio/.venv/bin/python Tools/audio/render_voices.py --preview   # one audition file per speaker in Tools/audio/preview/
```

### Who gets to talk

`VoiceDirector` rations voices so twenty robots don't turn into noise:

- The Overseer outranks heroes. Heroes don't start lines while Grok is talking, except to answer a click. A critical alert interrupts a lesson. A scripted line that arrives while Grok is busy waits up to 8 s for its turn.
- Clicking a hero always gets an answer (with a double-click debounce).
- Unselected heroes speak only at big moments (claim, flee, level up, refused by orders, down). Routine moments (hunt, repair, rest, wander) are voiced for the selected hero only.
- At most 2 hero voices at once, 0.9 s between line starts, per-hero cooldowns. Hurt barks are rate-limited across the whole colony.
- Voices duck music and ambience while they play. Hero voices are partly spatialised and follow the robot. The selected hero sounds closer.

### Live lines (optional)

With the local LLM narrator on ([HERO_NARRATION.md](HERO_NARRATION.md)), heroes can say their own LLM-written lines aloud:

```bash
Tools/local_ai/start_narrator.sh --no-game   # now also starts voice_server.py on :8081 if Tools/audio is set up
```

In the editor, Settings → **HERO VOICES · LOCAL AI** enables both links. You can also use `-voice-server [url]` or `SOLAR_VOICE_URL`. When the narrator takes a moment, the hero waits up to 4.5 s for its line and the voice server speaks it in the same character voice. Otherwise the hero plays its bark. Overseer warnings with no baked line (alerts with module names in them, say) also go live when the server is up. Interpolated `CompactGrok` log lines stay text for now.

The server binds to 127.0.0.1 only, accepts cast names only, caps input at 240 characters, and caches recent lines. It answers `GET /health` and `POST /v1/audio/speech` (`{"input": "...", "voice": "hero.EngineerBot"}` → WAV). Expect about 1–2 s per line on Apple Silicon.

### Code

- `Systems/Voice/VoiceBank.cs`: manifest parsing, bark takes (never the same take twice in a row), line keys. Pure.
- `Systems/Voice/VoiceDirector.cs`: who may speak now. Pure.
- `Systems/Voice/WavDecoder.cs`: WAV bytes → samples for live lines. Pure.
- `Runtime/Audio/CharacterVoice.cs`: hero barks, voice sources, narration hand-off.
- `Runtime/Audio/OverseerVoice.cs`: Grok's voice and fallbacks.
- `Runtime/Audio/VoiceServerLink.cs`: the local TTS client (off the main thread, no proxy).
- `Editor/AudioImportRules.cs`: import settings by folder (music streamed, voices compressed in memory, SFX decoded on load).
- Tests: `Tests/EditMode/VoiceTests.cs`.
